---
title: The viewer
description: What a viewer sees when they open your link.
---

The link opens a read-only page in the browser. There is nothing to install and
nothing to sign in to, and nothing on it can write back to your disk.

## Files and code

- A **file tree** of the project, with a mark on files that changed in the
  checkpoint being viewed. Build folders appear as empty stubs.
- **Quick open**: press <kbd>⌘</kbd> <kbd>P</kbd> (<kbd>Ctrl</kbd> <kbd>P</kbd>
  elsewhere) to jump to any file by name.
- **Tabs and breadcrumbs** for the files you have open.
- **Syntax highlighting** that follows the page's light or dark theme, or one
  of the editor themes from the theme picker.
- File actions: copy the contents, copy the path, download the file, wrap long
  lines.

## Following along

While a broadcast is live, **Follow** opens each file as it is saved, so a
viewer who just watches sees what you are working on. Browsing an older
checkpoint pauses it, and a prompt offers to jump back to the latest.

## Timeline

The **Timeline** lists every checkpoint, newest first, with the files it
changed and how many lines were added and removed. Selecting one shows a diff
for each file and marks the changes in the tree.

- **Compare** shows the open file against an earlier version, unified or side
  by side.
- **File history** lists every checkpoint that touched the open file.

When a checkpoint is selected, **Copy checkpoint link** opens that point in the
timeline for anyone who already has access to the session. Named checkpoints
display the label the broadcaster gave them.

## When the broadcast stops

A stopped broadcast stays viewable: the files show their final state and the
timeline is intact. If the same directory is started again, the same link wakes
up with the new changes.

## What the viewer loads

The viewer makes requests to its own origin and to the biga server, and to
nothing else. The editor, its syntax highlighter, the fonts and the file icons
are all bundled with the site, so opening a link does not tell a third party
that you did. The page enforces this with a Content Security Policy that only
allows the site and the API, and it sends no referrer to other sites, so the
session link is never passed on.

If you serve the site and the server from different origins, set
`NEXT_PUBLIC_BIGA_API_URL` when you build the site. That origin is added to the
policy automatically; see [Self-hosting](/docs/self-hosting).
