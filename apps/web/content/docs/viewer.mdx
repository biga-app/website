---
title: The viewer
description: What a viewer sees when they open your link.
---

The link opens a read-only page in the browser. There is nothing to install and
nothing to sign in to, and nothing on it can write back to your disk.

## Files and code

- A **file tree** of the project, with a mark on files that changed in the
  checkpoint being viewed. Build folders appear as empty stubs.
- **Tabs** for the files you have open, with breadcrumbs under them. Right-click
  a tab (or press <kbd>Shift</kbd> <kbd>F10</kbd> on it) for close, close
  others, close to the right, close all, move, copy path or link, reveal in
  files and split right. Drag tabs to reorder them. Open tabs come back when
  you reload the page.
- **Syntax highlighting** that follows the page's light or dark theme, or one
  of the editor themes from the theme picker.
- File actions: copy the contents, copy the path, copy a link to the file or a
  line, download the file, wrap long lines.
- A brief highlight on the lines that just changed when the open file is
  updated live, with a mark on the scrollbar for changes out of view. With
  reduced motion on, the highlight is static instead of fading.

### Menus, palette and shortcuts

Every action lives in one place and is reachable three ways: the **menubar**
(File, View, Go, Help), the **command palette**, and a keyboard shortcut.

The palette opens in three modes. <kbd>⌘</kbd> <kbd>P</kbd> goes to a file by
name. <kbd>⌘</kbd> <kbd>K</kbd> opens the command list, and typing `>` in the
file box switches to it. Typing `:` and a number jumps to that line of the open
file. Use <kbd>Ctrl</kbd> instead of <kbd>⌘</kbd> outside macOS.

| Shortcut | Action |
| --- | --- |
| <kbd>⌘</kbd> <kbd>P</kbd> | Go to file |
| <kbd>⌘</kbd> <kbd>K</kbd> or <kbd>F1</kbd> | Command palette |
| <kbd>⌘</kbd> <kbd>B</kbd> | Show or hide the sidebar |
| <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>F</kbd> | Search in files |
| <kbd>⌘</kbd> <kbd>J</kbd> | Show or hide the bottom panel |
| <kbd>⌘</kbd> <kbd>&#92;</kbd> | Split right |
| <kbd>Alt</kbd> <kbd>W</kbd> | Close the tab |
| <kbd>Alt</kbd> <kbd>Shift</kbd> <kbd>W</kbd> | Close all tabs |
| <kbd>Alt</kbd> <kbd>Shift</kbd> <kbd>T</kbd> | Reopen the last closed tab |
| <kbd>Alt</kbd> <kbd>[</kbd> and <kbd>Alt</kbd> <kbd>]</kbd> | Previous and next tab |
| <kbd>?</kbd> | List every shortcut |

Right-clicking a file, a folder, a checkpoint or empty space in the tree and
timeline opens a menu with the actions that make sense there.

### Search in files

<kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>F</kbd> opens **Search** in the sidebar. It reads
the shared files in your browser, so it also works for encrypted sessions, where
the server could not search. Options match case, whole words or a regular
expression. Binary files and files over 1 MB are skipped, and results stop at
2,000 matches. Choosing a result opens the file at that line, and the search
can be limited to one folder from the folder's menu.

### Split view

**Split right** opens a second editor beside the first. Each side has its own
tabs, and the file you open next goes to whichever side you last used. Close the
split from the View menu or the palette.

### Overview

**Overview** is the session at a glance: its status and last save, how many
files and checkpoints it has, how much changed, a chart of saves over time, the
most changed files, the languages used and the share link. It opens when you
close every tab, and from the first tab in the strip.

### Status bar and panel

The bar along the bottom shows the connection state and the age of the last
save, the latest checkpoint, whether Follow is on, the cursor position, the
language and whether long lines wrap. Most parts are buttons. <kbd>⌘</kbd>
<kbd>J</kbd> opens a panel beneath the editor with the files in the current
checkpoint and a log of every save as it arrives.

**Layouts** in the View menu arrange all of this in one step: *Default*, *Review*
(timeline, diffs and the changes panel) and *Focus* (editor only).

### Keyboard

The file tree follows the standard tree pattern: <kbd>↑</kbd> and <kbd>↓</kbd>
move, <kbd>→</kbd> opens a folder or steps into it, <kbd>←</kbd> closes it or
steps out, <kbd>Home</kbd> and <kbd>End</kbd> jump to the ends, and
<kbd>Enter</kbd> opens a file. Typing a few letters jumps to a matching name.
Tab leaves the tree rather than stepping through every row.

### Large files

Files over about 256 KB, or with more than 20,000 lines, open with code
folding, bracket colours and sticky scroll switched off so the page stays
responsive. Files over about 2 MB, or with a single line longer than 20,000
characters (minified bundles, for example), open as plain text with a notice
and an **Enable highlighting** button. The notice appears above the editor, so
screen readers reach it first.

## Following along

While a broadcast is live, **Follow** opens each file as it is saved, so a
viewer who just watches sees what you are working on. Browsing an older
checkpoint pauses it, and a prompt offers to jump back to the latest.

## Links

Every view has its own address, so you can share what you are looking at and
Back and Forward behave as you expect.

| Address | Shows |
| --- | --- |
| `/session/<id>` | The latest state, following along. |
| `/session/<id>?file=<path>` | That file. |
| `/session/<id>?file=<path>&base=start` | The file compared with the first checkpoint. `base` can also be a checkpoint number. |
| `/session/<id>?file=<path>&line=<n>` | That file, scrolled to and highlighting that line. |
| `/session/<id>?file=<path>&split=<path>` | Two files side by side. |
| `/session/<id>?overview=1` | The session overview. |
| `/session/<id>?checkpoint=<n>` | The timeline, open on that checkpoint. |
| `/session/<id>?checkpoint=<n>&file=<path>` | That file's diff in that checkpoint. |

Opening a file yourself adds a history entry, so Back returns to the previous
file. Following along, switching the comparison and stepping through
checkpoints replace the current entry instead, so a live broadcast does not
fill your history. Invalid values are ignored and the latest state is shown.

## Timeline

The **Timeline** lists every checkpoint, newest first, with the files it
changed and how many lines were added and removed. Selecting one shows a diff
for each file and marks the changes in the tree.

- **Compare** shows the open file against an earlier version, unified or side
  by side.
- **File history** lists every checkpoint that touched the open file.

When a checkpoint is selected, **Copy checkpoint link** opens that point in the
timeline for anyone who already has access to the session. Named checkpoints
display the label the broadcaster gave them.

## If the connection drops

The page keeps showing the last state it had, says **Reconnecting**, and retries
on its own. Once it has given up it shows **Offline** with a button to try
again, and it tries again by itself when the browser comes back online. See
[how the viewer applies events](/docs/architecture#how-the-viewer-applies-events)
for the details.

## When the broadcast stops

A stopped broadcast stays viewable: the files show their final state and the
timeline is intact. If the same directory is started again, the same link wakes
up with the new changes.

## What the viewer loads

The viewer makes requests to its own origin and to the biga server, and to
nothing else. The editor, its syntax highlighter, the fonts and the file icons
are all bundled with the site, so opening a link does not tell a third party
that you did. The page enforces this with a Content Security Policy that only
allows the site and the API, and it sends no referrer to other sites, so the
session link is never passed on.

If you serve the site and the server from different origins, set
`NEXT_PUBLIC_BIGA_API_URL` when you build the site. That origin is added to the
policy automatically; see [Self-hosting](/docs/self-hosting).
